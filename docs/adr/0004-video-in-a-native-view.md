# Video plays in a native view over the panel

The desktop app plays match video with libmpv (PRD: frame-accurate seek and frame stepping, every codec, no webview media engine) drawing into a native view that the backend lays over the video panel of the Tauri window; the Svelte UI reports the panel's bounds as the layout changes and drives playback through commands (`video_open`, `video_place`, `video_command`, `video_state`). We bind libmpv ourselves (`libmpv2` crate, `wid` set to the view) rather than use `tauri-plugin-libmpv`, which is untested on macOS, has no working embedding on Linux, and downloads a prebuilt wrapper library at setup; and we draw over the webview rather than behind a transparent one, so the rest of the UI keeps its own background. The cost: anything the webview draws over the panel (menus, dialogs) is hidden under the video, so the panel hides the view while such UI is open. macOS works (mpv picks Vulkan via MoltenVK and VideoToolbox decoding). Windows uses a child window (a `STATIC` control) of the Tauri window, raised above the webview's on every move, and Linux an X11 child window of the GTK window's X window on its own Xlib connection, in physical pixels on both; under Wayland it needs XWayland (`GDK_BACKEND=x11`), as a native Wayland surface would need mpv's render API. Both are written and type-checked but not yet run on those systems; how mpv is shipped per platform is still open (PRD).
