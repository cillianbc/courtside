# The desktop engine and store run in the Rust backend

In the desktop app, vb-engine and the SQLite season database live in the Tauri backend: the Svelte UI sends codes and commands and receives state snapshots, and every log event (code, correction, undo) is written as its own row in one transaction before the UI sees the new state. We chose this over running the engine as WASM in the webview (courtside-ffi already builds it) because it keeps one writer and one copy of match state, saves survive a webview crash, and nothing typed is lost. A match is stored as event rows replayed into vb-engine on open, plus match/team/player tables for the .dvw headers, not as .dvw text, so the history and corrections stay queryable; imported matches also keep their source .dvw bytes for lossless export. WASM remains the path for the web bench viewer (phase 4).
