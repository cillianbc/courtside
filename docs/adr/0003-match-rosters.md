# Each match keeps its own roster

A season's teams and players are edited in the console (team editor, roster grid, merges, team-file import), and a player has a stable id and a code unique in the season, written to the `.dvw` player id column, so analysis can follow a player across matches. When a match is created or imported, both rosters are copied into `match_player`, and the match is built and exported from that copy, not from the live team. Editing a team's roster later never rewrites a match already coded, and a late addition or corrected number can be made for one match only; the copy keeps a link to the season player for analysis. We chose this over building every match from the live team tables, which would silently change past exports, and it matches how scouts work in VolleyStation, whose matches have their own player list (docs/research/VOLLEYSTATION.md §10). For a match imported from a file, its roster starts as the file's and edits are written back into the file's `[3PLAYERS]` rows on open and export: unchanged rows stay byte for byte, changed ones have only the edited fields rewritten (with DataVolley's Unicode copy where the row has one), new players get rows in the file's style.
